## 2. 运行形态

同一镜像 `kb-p1-portal:1.0.0` 由 `KB_ROLE` 派生两种角色：

- `api`：HTTP、上传、问答、审计写、outbox 发布；发布宿主回环 18181。
- `worker`：`IngestConsumer`、`RetryPump`、`LeaseHeartbeat` 才装配；不发布端口。
- `gateway`：nginx 1.27，TLS 8443，8080 只做 308 跳转；SSE 关闭缓冲、读超时 300s。

网络沿用 P0 两层结构：`kb-p0_p0-backend` 为 internal 网络承载全部服务间流量，
`kb-p0_p0-ingress` 仅用于宿主机端口映射。只挂 internal 网络时 `ports:` 不会真正发布。

## 3. 各专项实现要点

### #18 真退避

- 失败任务写 `RETRY_SCHEDULED` + `next_run_at = now + min(base * 2^(attempt-1), max)`，并清空 `retry_notified_at`。
- `claimTask` 的条件包含 `next_run_at <= now`，未到期任务任何 worker 都抢不到，不靠 sleep。
- `RetryPump` 只对“到期且未通知”的任务写入 retry outbox；eventId 用 `UUID.nameUUIDFromBytes(taskId + ":" + attempts)`，
  重复扫描、重复投递都被 `event_consumption` 账本吸收。
- 租约 45s、心跳 15s；心跳只续自己持有的租约，过期租约不能被复活。

### #4 审计事务化与哈希链

- 业务写与 `audit_event` 同事务（`recordInTx` 为 MANDATORY）；审计失败业务整体回滚。
- 登录/登出/安全敏感读用 REQUIRES_NEW（`recordIndependent`），失败则 fail-close。
- 链头 `audit_head` 按租户行锁串行；`record_hash` 覆盖全部字段 + `created_at` 毫秒 + `prev_hash`。
- `metadata_json` 改为 `MEDIUMTEXT`：MySQL JSON 列会补空格/重排，读回值不再等于写入字节，链校验必失败。
- 审计时间先 `truncatedTo(MILLIS)`：DATETIME(3) 会对第 4 位小数四舍五入，否则哈希与库值偶发不一致。
- 外发通过 `outbox_event` 同事务写入，Kafka 不可用只延迟外发。

### #5 ACL 版本缓存

- 权限写入后递增 `knowledge_base.acl_version`；缓存键为 `p1:acl:{kbId}:{userId}:v{version}`。
- 指针键 `p1:aclp:{kbId}:{userId}` 指向当前版本；旧版本键即使残留也永远不会被读取。
- 失效时按指针精确删除，再删指针；新版本未命中时回源 MySQL 并重填。
- Redis 故障时直接回源数据库，不把“缓存不可用”当成“无权限”。

### #3 拒答语义

- 空输出或以 `NO_ANSWER` 开头的模型输出判定为拒答；证据不足时状态为 `NO_EVIDENCE`。
- `REFUSED` / `NO_EVIDENCE` 只写回答、状态与审计，**零引用**；仅 `ANSWERED` 写 `citation`。
- 引用编号与送入 prompt 的候选编号一致，越界引用被丢弃并计入 `dropped_by_unsupported_citation`。

### #1 WeKnora 适配器

- 适配器覆盖建库/索引/删除/检索/删除库/健康六类调用，HTTP 路径可配置。
- 检索结果强制校验 `tenant_id`、`knowledge_base_ids`、文档版本与分块元数据；缺失或越界直接丢弃。
- 空 scope 不发请求，避免“无范围=全库”的越权检索。
- 启动能力探测：引擎不支持租户隔离时以 `ENGINE_ACL_UNSUPPORTED` fail-close，不降级放行。

### #6 账号拆分

- Flyway 使用 `kb_p1_ddl`（仅迁移时），运行账号 `kb_p1_app` 只有 SELECT/INSERT/UPDATE/DELETE。
- 启动时 `SHOW GRANTS FOR CURRENT_USER()` 校验，发现 CREATE/DROP/ALTER/GRANT/ALL 即拒绝启动。
- 实测：应用账号 `CREATE TABLE` 报 1142，Flyway 用 DDL 账号成功应用 V1–V11。

## 5. 实现过程中发现并修复的缺陷

1. `audit_event.metadata_json` 使用 JSON 列导致读回值被规范化，哈希链必错 → `V11` 改 `MEDIUMTEXT`。
2. 审计时间未截断到毫秒，DATETIME(3) 四舍五入导致链校验偶发失败 → `Instant.truncatedTo(MILLIS)`。
3. WeKnora token 为空时调用 `headers(String[0])` 抛 `wrong number, 0, of parameters` → 改为按需添加 Authorization。
4. OIDC issuer 为空时仍注册客户端发现 bean 导致启动即连接失败 → `@ConditionalOnExpression` + 非 dev 缺 issuer 明确拒绝启动。
5. 容器内 Redis 端口误用宿主映射 16379 → compose 固定 `KB_REDIS_PORT=6379`；internal 网络下端口不发布 → api/gateway 增加 ingress 网络。
6. 网关 HTTP→HTTPS 跳转误用 `$server_port`（8080）→ 固定跳 8443。
7. **明文口令出现在交付物**：`p1/compose/README.md` 的建号 SQL 直接写死 `kb_p1_ddl/kb_p1_app` 口令，
   `FlywayMigrationTest`/`P1CoreIntegrationTest` 用 `env(KEY, "真实口令")` 兜底（含 MinIO secret、Redis 口令）
   → 文档改为从 `p1/compose/secrets/*.txt` 读入；测试改为 `TestSecrets.secret(变量名)`：
   环境变量优先、其次读 secrets 文件、两者皆缺即失败并指名要哪个变量/文件。
   复跑：`cd p1/portal && mvn -o clean test` → 28/28 通过（2026-11-01，本机未设任何 `KB_TEST_*`，走 secrets 文件分支）。
8. `.gitignore` 的排除形同虚设两处：`p1/compose/secrets/`、`p1/compose/nginx/certs/` 未列入（p1 与 p0 同构但规则只写了 p0）；
   原始问答记录的规则少一层目录（指向 `p0/evaluation/`，实际文件在 `p0/evaluation/reports/quality-raw.jsonl`），
   业务语料正文实际不在排除范围内 → 补齐三条规则＋改正路径，并新增根 `.tmp/`；
   由门禁脚本 `check-hygiene.cjs` 的第 4/5 项复现与验证。
