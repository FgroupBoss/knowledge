## 3. 实现要点（与契约的差异都写在这里）

- **三轴正交**（ADR-011）：PAGE 6 态 / REVISION 5 态 / SYNC 8 态，21 条边；`freshness` 是派生位、
  没有出边。迁移全部 `UPDATE … WHERE status = 前置态`，0 行 → `INVALID_STATE_TRANSITION`(409) + `DENY` 审计。
- **`submit` 可以不走 PAGE 轴**：已发布页面提新修订只走 R1，页面留 `PUBLISHED`，
  审核通过才由 E4/R4 换指针。实现里若要求"submit 必须有 PAGE 出边"，E4/R4 就永远产不出来
  （已写进 `state-machine-wiki.md` §2；用例 `secondRevisionReplacesThePublishedPointer`
  断言审计里 `pageEdge=NONE`）。
- **审核能力只来自指派行**（ADR-012）：`review = 角色 ∈ {OWNER, ADMIN} || 被指派`；
  `readDraft = 作者 || review || owner`，**故意不含 `write`**。W1 无指派端点，靠 SQL 引导（backlog #27）。
- **冲突显式失败**（ADR-013）：草稿保存靠 `current_revision_no` 条件更新，409 `WIKI_REVISION_LOST`
  只回 `currentRevisionNo`/`latestRevisionNo`/`latestBodyDigest12`，不回传他人正文；
  治理位 PATCH 靠 `acl_version`，409 `VERSION_CONFLICT`。状态迁移每次都会 `acl_version + 1`，
  所以 PATCH 的 `If-Match` 必须从最新视图读，不能假想是 0/1/2。
- **来源 fail-close**（D-10）：无可用来源不得提交；来源文档变 `DELETED`/版本不符只把该来源标成
  不可用，已发布正文仍可读。来源挂在**修订**上，新修订必须自带来源才提得交。
- **审计**（红线 1）：正文与审核意见原文只留摘要（`decision_note_digest`）；
  `recordInTx` 为 MANDATORY，DENY 走独立事务所以不随业务回滚，ALLOW 随业务同生同灭。
