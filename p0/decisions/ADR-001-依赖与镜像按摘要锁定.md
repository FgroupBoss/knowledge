# ADR-001 依赖与镜像一律按摘要锁定，验证环境不联网拉包

- 状态：已采纳（2026-10-31）
- 背景：P0 要求"所有依赖固定版本且无 `latest`"。本机 Docker 镜像加速站只对 `library/*` 命名空间放行，
  非官方仓库一律 403；Maven 也必须能离线跑，否则换台机器结论不可复现。
- 决定：
  1. Compose 里每个镜像都写成 `name:tag@sha256:...` 双锁定（tag 给人看，digest 给机器用），
     `minio/mc` 只有 digest 引用；禁止 `latest`。
  2. Java 侧用 `mvn -B -o`（离线）构建，本地仓库 `D:\localResp`；版本由
     Spring Boot 3.5.16 / JDK 21.0.9 / MyBatis starter 3.0.5 / MinIO client 8.5.17 /
     PDFBox 3.0.3 / POI 5.4.1 固定，无浮动版本。
  3. 每次环境变动后用 `scripts/02-image-manifest.sh` 重生成 `compose/image-manifest.txt`
     （含 toolchain 与本地 Ollama 模型清单），交付包里带这份清单。
- 后果：
  - 正面：换机复现只需要"镜像已在本地 + 本地 Maven 仓库"，不需要外网；演练期间任何"顺手拉个新镜像"
    都会在 `docker run` 阶段失败，而不是悄悄改变结论。
  - 负面：拿不到 `library` 之外的镜像（直接导致 ADR-003 的引擎缺口），升级必须人工换 digest。
- 证据：`compose/image-manifest.txt`、`compose/docker-compose.yml`、`p0/evaluation/reports/offline-drill.md` OF-01。
- 责任人 / 复测：平台运维；P1 每次换镜像时重跑 `02-image-manifest.sh` 并比对摘要（首轮 2026-11-06）。
