# ADR-006 上传只收十种格式并做签名校验，证据预算按分数贪心且不跳着拼

- 状态：已采纳（2026-10-31）
- 背景：原件是唯一权威（索引是派生物），一旦放进坏文件后面全部指标都失真；
  同时 Prompt 里塞几条证据直接影响"引用可回溯"这件事能不能成立。
- 决定：
  1. 上传卡口：`P0_UPLOAD_MAX_BYTES=104857600`（100MiB），并且与
     `spring.servlet.multipart.max-file-size` 同值（`max-request-size` 多留 10MiB 给 multipart 边框），
     两处不一致就会出现"应用放行、容器截断"的假成功；并发上限 `P0_UPLOAD_MAX_CONCURRENT=3`，
     超了直接 429 `CONCURRENCY_LIMITED`，不落临时文件。
  2. 格式白名单（不是黑名单）：`md,txt,csv,tsv,json,log,pdf,docx,xlsx,pptx`；
     扩展名不在表内 → 422 `DOCUMENT_FORMAT_UNSUPPORTED`；
     扩展名与内容签名不符（如假 PDF）→ 422 `DOCUMENT_SIGNATURE_MISMATCH`；空文件 → 400。
  3. **无文字层的扫描件按永久失败处理**，不在 P0 偷偷上 OCR：解析不出文本就当格式不支持，
     这样缺口是显式证据（`quality-baseline.md` EV-04）而不是一句"以后支持"。
  4. 切分与预算：分片 800 字符、重叠 120；召回 `topK=20` 是**超取数**，逐条复核后仍保留富余，
     真正进 Prompt 的上限是 `context-chunks=6`；Prompt 预算 `P0_MODEL_MAX_PROMPT_CHARS=4096`，
     按 score 从高到低贪心填充，第一条装不下就停止——保证引用是连续断号，不会出现"引了 1、3、5 条"
     这种暗示模型跳过证据的拼接。
  5. 引用落库只写复核后仍可用的片段，片段正文截到 2000 字符并带 `snippetDigest`，
     完整内容由服务端代理 `preview` 取（ADR-002）。
- 后果：
  - 正面：坏文件进不了权威存储；Recall/支持率的判定分母干净（EV-08 实测预算未截断前 5 条）。
  - 负面：扫描件与图片类文档这条 P0 完全不支持，业务侧必须有"先出文本层"的流程约定；
    4096 字符预算在长合同类文档上会截断到 3~4 条证据，生产语料上必须重新校准（P1）。
- 证据：`evaluation/reports/ingest-run.md`（UP/LIM 家族）、
  `evaluation/reports/quality-baseline.md`（EV-03 十种格式全 READY、EV-04 扫描件永久失败不入索引、
  EV-08 预算未截断 0/120）、`contracts/config-catalog.md` 上传与模型段落。
- 责任人 / 复测：业务 + Java；拿到生产语料后重估分片大小、`context-chunks` 与 Prompt 预算（2026-11-20 前），
  OCR 是否进范围由业务决定并另开 ADR。
