# ADR-014 `p1/contracts` 是 pilot 侧契约事实源，门禁扩展而非放宽

- 状态：已采纳（W0）（2026-11-01）
- 背景：AGENTS.md §2 把契约事实源定在 `p0/contracts/`，但那份是 P0 验证期的口径：
  OpenAPI 只有 17 条路径、错误码表只覆盖 P0 码、`04-check-contracts.py` 只看 `com.acme.kb.p0.pipeline.Events`。
  P1/P2 的接口、`kb.audit.v1`、`KB_*` 配置、Wiki 状态机都散落着"文字契约 + 代码"两本账
  （backlog #20、#22 就是这么来的）。D 级取舍：再建一套 pilot 侧事实源会与 P0 冲突，
  不建则每次改动都要人工三方核对。
- 决定：
  1. **加法分文件，不改 P0 冻结件**：`p1/contracts/openapi-1.2.yaml`（33 操作）、
     `p1/contracts/error-codes.md`（31 码，含补登记的 4 个历史欠账）、
     `p1/contracts/state-machine-wiki.md`（21 条边 + §5 负向用例表）、
     `p1/contracts/config-catalog-p1.md`（`KB_*` 三层同名）、
     `p1/contracts/weknora-adapter.md`（保持"未在真机验证故未冻结"）。
     主题与 schema 仍只有一份，留在 `p0/contracts/kafka/`（向后兼容、`schemaVersion` 递增）。
  2. 新校验放 `p1/scripts/24-check-contracts-p1.py`，**不碰 `04` 的判定语义**（AGENTS 硬性规则 4）；
     `04` 继续只管 P0 侧。扩展方向单向：新校验只允许新增 ERROR，任何情况下不把既有 ERROR 降级。
  3. 每条校验必须能自证不是空跑：`--selftest` 用内存态突变（改属性名、删码表行、改分类列、
     让码不可产生、删边、加幽灵边、改载荷键名、加未声明路径）证明改坏必报错。
  4. 冲突裁定顺序不变：**冻结契约文件 > 代码 > 散文**；契约里标【实现未达成】的段落是目标，不是现状。
- 后果：
  - 正面：改 P1/P2 的码表、配置、事件字段、状态机边时有一条命令能报漂移；
    三方核对（契约 ↔ Java ↔ 文档）从"人工记着"变成退出码。
  - 负面：契约事实源从 1 处变 2 处，读的人要先看 §2 的地图；`p1/contracts` 目前**不在 git 里**
    （本目录不是仓库），误删只能靠复核跑脚本发现。
  - 已知缺口：x-error-codes 的可产生性只核对到**全局**，没按单个操作核对，
    所以 `getWikiPage` 声明了 detail 路径产不出的 `INVALID_STATE_TRANSITION` 不会报警（backlog #29）。
- 证据：`p1/evaluation/reports/p2-wiki-contracts-and-w1.md` PW-18（`0 error / 0 warning` + 自检 11/11）、
  PW-04（边表逐条比对）、PW-19（迁移副本逐文件 SHA-256）、PW-20（主题三处一致）；
  复跑：`python p1/scripts/24-check-contracts-p1.py --selftest && python p0/scripts/04-check-contracts.py`。
- 责任人 / 复测：Java；每加一个 P1/P2 端点、错误码或配置项时同批补校验（W2 开工前复跑一次，2026-11-13）。
